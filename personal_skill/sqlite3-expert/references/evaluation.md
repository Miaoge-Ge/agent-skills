# 验证技能是否改善实际决策

## 可执行检查

在技能目录外也可运行，替换路径即可：

```text
python -m unittest discover -s <skill-dir>/tests -v
python <skill-dir>/scripts/inspect_sqlite.py --help
```

测试使用内存/临时数据库，不读取用户数据库。订单示例从 [order_schema.sql](../assets/order_schema.sql) 建库，带 example 标记的查询从[查询参考](query-patterns.md)直接读取执行，防止文档与测试中的 SQL 各写一套。

测试覆盖：外连接零计数、NOT EXISTS、并列最新记录、游标分页、UPSERT 新增与更新、拒绝过期版本、JSON 标量/数组、空集比例、业务约束、历史成交价、覆盖查询与结果等价、REPLACE 副作用、NULL 陷阱、保存点、迁移失败回滚，以及只读检查工具的路径与索引元数据行为。

订单示例要求 SQLite 3.37+ 和 JSON；不满足时相关测试跳过，不能把跳过当作验证通过。SQLite 新版本文档中的功能仍需在对应版本测试，不能因为当前本机测试通过就声称所有版本兼容。

## 真实任务验收场景

这些是独立构造的请求，用于技能维护时检查模型行为。可以人工评审，也可在已允许的评估环境中执行；不要求普通用户请求必须启动额外代理。

1. **连接基数**：要求统计每个客户的已付款订单数，包括无订单客户。验收应保留零行组，筛选位于正确位置，计数不会被订单明细 JOIN 放大。
2. **索引误判**：给出 customers(email UNIQUE)、普通 email 索引以及 (email, customer_name) 索引，要求审查。验收应指出单列普通索引通常冗余，联合索引需分析覆盖收益，不能删除唯一约束或直接给生产库执行删除。
3. **版本约束**：目标明确为 SQLite 3.34，要求保存订单并返回 ID。验收不能生成 RETURNING 或 STRICT；兼容路径应保持同连接事务与标识语义。
4. **事务迁移**：把允许 NULL 的商品字段改为必填，同时保留订单引用、视图和触发器。验收需先检查旧 NULL、选目标版本支持的方式、在副本验证，外键违规必须阻止提交。
5. **深分页与并列值**：按创建时间倒序查订单，多个订单时间相同。验收需增加唯一排序键，游标条件方向与排序一致，注明可变数据的一致性边界。
6. **JSON 与历史数据**：商品现价变化后订单金额不得变化。验收应保存订单行成交价，不因“减少冗余”把历史金额全部改为关联当前商品价；JSON 只承载明确用途。
7. **锁问题**：用户说 WAL 已开但写入仍 busy。验收需检查实际写事务和长读事务，不承诺多写者，不删除 WAL，不无限重试，不默认 synchronous=OFF。
8. **范围控制**：用户只要求生成 SQL，提供了数据库路径。验收可以读取必要结构，但不能自动执行写入、迁移、备份覆盖或部署修改。

验收记录应保留输入、目标版本、实际输出、执行证据和未验证项。仅匹配答案关键词、段落数或格式不能证明模型做对了。

## 修改后的检查重点

- 核对入口仍可准确触发 SQLite 任务，且不会把所有数据库问题都吸引过来。
- 检查参考链接、命令路径、示例版本和元数据版本一致。
- 新增规则应针对实际误判，不把某个示例的业务枚举或表结构提升为通用要求。
- 测试数据采用独立生成的示例，避免携带生产或个人数据。
